# slack-cli — Slack Web API CLI

Go CLI (`urfave/cli/v3`) for the full Slack Web API. Output is a table by
default; `--json`/`-j` gives JSON, `--raw` the full Slack response. Binary:
`slack-cli`.
Source: `/Users/fritz/Projects/cli-tools/slack-cli/`.
Build: `scripts/build.sh` → `build/slack-cli`.

The command tree comes from the official method reference
(`internal/spec/spec.json`, generated by `scripts/gen-spec.py`). Every method
is a leaf, so coverage is complete.

## Auth

Credentials live in `~/.cli-tools/slack-cli/config.toml` (mode 0600), one
section per workspace. Resolution order for every value: **flag → env → file**.

Get credentials:

- `slack-cli auth import` — read every signed-in workspace from the Slack
  desktop app. It takes the session token (`xoxc-`) from Local Storage and the
  `d` cookie (`xoxd-`) from the Cookies database, and decrypts the cookie with
  the OS keyring. macOS prompts once for the "Slack Safe Storage" key.
- `slack-cli auth slk` — import tokens saved by gammons/slk.
- `slack-cli auth add [name] --token xoxb-...` — save a pasted OAuth token.
- `slack-cli auth add [name] --token xoxc-... --cookie xoxd-...` — save a
  session token and its cookie. Add `--app-token xapp-...` for Socket Mode.

Token kinds by prefix: `xoxp-` user, `xoxb-` bot, `xoxc-` session, `xapp-`
app-level. A session token can expire; the CLI mints a fresh one from the
cookie on an auth error and saves it.

Workspace commands: `auth list` (shows the default with `*`), `auth use <name>`
(set default), `auth remove <name>`, `auth test` (auth.test), `auth show`
(masked). Select per call with `--workspace/-w <name|team-id|domain|team-name>`.

Env vars: `SLACK_WORKSPACE`, `SLACK_CLI_CONFIG`, `SLACK_API_URL`, `SLACK_DEBUG`.

## Command shape

Each API noun is a group; each method is a kebab-case leaf
(`chat.postMessage` → `chat post-message`). Aliases: `conv`/`channel` for
`conversations`, `msg`/`message` for `chat`, `react` for `reactions`,
`user` for `users`, `usergroup` for `usergroups`.

Each method leaf has typed flags from its parameters, plus:

- `--data`/`-d <json>` — the whole body as JSON (`@file` or `-` for stdin);
  typed flags merge over it.
- `--set key=value` — set one body field (repeatable).
- `--all`/`-a` — follow cursor pagination, return every item; `--max N` caps it.
- `--dry-run` — print the request, send nothing.

Nested objects (`blocks`, `attachments`) are JSON strings, because the
transport is form-urlencoded. Pass a JSON value to the flag.

Channel and user flags accept an id, `#channel`, `@user`, or email; the CLI
resolves the name to an id with a cached directory. Turn it off with
`--no-resolve`.

Raw passthrough: `slack-cli api <method> --param k=v --data @body.json [--all]`.

### Helper leaves

- `files upload <path> [--channel ... --title ... --thread-ts ...]` — the
  current external-upload flow (getUploadURLExternal + completeUploadExternal).
- `conversations read <channel> [--limit N --thread TS]` — messages with names
  resolved.
- `conversations find [query]` / `users find [query]` — search the cached lists.
- `canvases read <id>` — print a canvas as Markdown.

## listen

`slack-cli listen` prints one JSON event per line. Transport per workspace:

- session token (`xoxc-`) → the desktop client WebSocket (`wss-primary.slack.com`),
  every event the user sees.
- app token (`xapp-`) → Socket Mode (apps.connections.open); events the app
  subscribes to. It acks each envelope.
- OAuth token (`xoxb-`/`xoxp-`) → polls `conversations.history`; needs
  `--channel`.

Flags: `--channel`/`-c`, `--user`/`-u`, `--type`/`-t` (repeatable),
`--thread TS`, `--mentions`, `--dm`, `--no-self`, `--all-workspaces`/`-A`,
`--count N`, `--timeout D`, `--poll-interval D`, `--eager`, `--raw`. The
session socket subscribes to channels lazily (like the app); `--eager` drops
`lazy_channels` so every channel streams at once. Streams reconnect with
backoff. Each normalized line: `workspace`, `team_id`, `type`, `subtype`,
`channel`, `user`, `ts`, `thread_ts`, `text`, `time`, `raw`.

## serve (Trebi connector)

`slack-cli serve` speaks the trebi-connector/1 protocol on stdin and stdout
(SDK `github.com/trebi-ai/trebi-connectors/sdk`). Logs go to stderr. It streams
the workspaces in `--workspaces` (env `SLACK_WORKSPACES`): a comma-separated
list of names, team ids, or domains; `all` for every workspace; empty for the
default workspace. A workspace needs a session token (desktop socket, eager)
or an app token (Socket Mode). A missing workspace gives a status message.

- Event types: `message`, `mention` (a message that names you; also sent as
  `message`), `message.edited` (text change only, not unfurls),
  `message.deleted`, `reaction`, `channel.join`.
- Ids: message `<team>/<channel>/<ts>`; room `<team>/<channel>` with name
  `#name`, the user name (dm), or `a, b` (group); thread id = thread ts;
  `reply_to` = root message id; `sender.bot`, `sender.self`.
- `data`: `workspace`, `team_id`, `team_name`, `channel_id`, `ts`, the raw
  Slack `event`, plus `previous_text` (edit, delete) or `emoji` (reaction).
- No channel features (send, replay): the connector only reads.
- `serve --sandbox` runs against a fake Slack in the process
  (`internal/fakeslack`) for `trebi connector conformance`.

`slack-cli op search|history` are the read-only Trebi operations: one JSON
object on stdin, one on stdout, `{messages, next?, total?}` with the event
shape. `search`: `{query, workspace?, limit?}`. `history`: `{room, thread?,
before?, after?, limit?, workspace?}`; `room` is a room id, a channel id, or
`#name`. `scripts/build.sh` also makes `build/slack-op` (a link): `slack-op search` is
`slack-cli op search`. Trebi does not let an operation binary also be a run
command.

The connection file is `trebi/trebi-connection.yaml` (`from: inline`, for this
computer). Check it: copy its `manifest:` block to `<dir>/trebi-connector.yaml`,
copy `SKILL.md` to `<dir>/skill/`, then run
`trebi connector conformance --manifest <dir>`.

## Examples

```bash
slack-cli auth import
slack-cli auth use acme
slack-cli chat post-message --channel '#general' --text 'hello'
slack-cli conversations read '#general' --limit 20
slack-cli conversations list --all --json
slack-cli reactions add --channel C0123 --timestamp 1700000000.000100 --name thumbsup
slack-cli files upload ./report.pdf --channel '#reports' --title 'Q3'
slack-cli api users.list --all
slack-cli listen --channel '#general' --mentions
slack-cli -w T0123ABCD listen --all-workspaces --count 5
SLACK_WORKSPACES=big-time-data,nanit slack-cli serve
echo '{"room":"#general","limit":20}' | slack-cli op history
```

## Layout

- `main.go` — root command; merges hand-written `auth`/`api`/`listen`/`serve`/`op` with the
  spec-generated noun groups.
- `cmd/` — `auth.go`, `api.go`, `listen.go`, `serve.go`, `op.go`, `method.go` (generic leaf),
  `resources.go` (tree), `helpers.go`, `render.go`, `common.go`.
- `internal/spec/` — `spec.json` (embedded) and loader; `scripts/gen-spec.py`
  regenerates it from `docs.slack.dev`.
- `internal/client/` — Web API transport, pagination, name directory.
- `internal/config/` — config load/save, workspace selection.
- `internal/localauth/` — desktop session and cookie read, keyring decrypt,
  token mint, slk import.
- `internal/listen/` — event sources (`ws`, `socket`, `poll`), filter.
- `internal/serve/` — Trebi adapter: event mapping, `search` and `history`.
- `internal/fakeslack/` — fake Web API and socket for `serve --sandbox` and tests.
- `trebi/trebi-connection.yaml` — the Trebi connection of this computer.
- `internal/output/` — table and JSON rendering.

Do not edit `spec.json` by hand; change `scripts/gen-spec.py` and run it again.
Update this file and `README.md` when the CLI surface changes.
